## Changed contracts

- x64 versioned factories return actual cached legacy C++ objects, or null for
  unsupported exact versions. Unknown export names no longer manufacture
  executable generic shims or string pointers. Requests/rejections are counted
  by export/version without dumping account data or argument memory.
- SteamUser016's 22 slots use concrete integer, one-byte bool, void, pointer,
  64-bit scalar and hidden class-return signatures. Flat SteamID is a scalar;
  classic SteamID writes eight bytes to its hidden result and returns that
  pointer. Factories and bare classic accessors use concrete signatures.
- All 27 SteamClient012 slots have concrete signatures; getters validate
  version and family, including the final unsupported UGC getter. Its vtable is
  no longer padded to impersonate newer versions. Unsupported bare classic
  families return null instead of an 80-slot catch-all object.
- Offline user methods never report logged-on, successful authentication or a
  fabricated ticket/license. Ticket/voice counts are zeroed within their
  declared width; buffers are not filled with synthetic tickets. Existing app
  subscription/storage semantics and the external account adapter are retained;
  authentic ticket/online service implementation remains WP11.
- Cached objects, vtables, delegates and UTF-8 strings are process-lifetime,
  rooted and locked on creation. Tracer closures also retain their recorder
  owner while cached traced slots can call it. Shutdown cancels queues/registrations, retaining
  cached pointers for reinit. Classic cancellation serializes with in-flight
  delivery; a callback can cancel a later target. Manual payloads are serialized
  and retained until FreeLastCallback or shutdown.
- x86 factories allow explicit implemented versions rather than prefixes;
  SteamUser016–019 use 22/24/25/29 declared slots, typed guest argument widths,
  hidden SteamID results and measured thiscall stack cleanup. Guest shutdown
  clears callback flags, queues and pending call results without invalidating
  cached objects. Offline auth
  failures initialize count outputs. Guest code and memory remain owned by its
  process. No x86 native host interface is exposed by the x64 UWP application.

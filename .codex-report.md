## Layer 1 — XInput export and event contract

- Added XInput 1.1/1.2 aliases, keystroke and audio endpoint discovery by name
  and ordinal to both host and x86 registration paths.
- Keystrokes drain button/trigger/stick transitions per controller, report
  ERROR_EMPTY after draining, and release old stick directions before new ones.
  Audio discovery reports absent endpoints without inventing devices.
- Reference: Valve Wine dc26e618, dlls/xinput1_3/main.c and XInput .spec files.
  Independent implementation; no Wine code copied. Like the inspected Wine
  transition path, key-repeat events are not synthesized yet.
- Tests: 549 passed, 1299 platform-skipped on arm64, zero failed. Linked the
  actual host PadBridge into tests with deterministic platform substitutes;
  verified alias exports, ANY-user polling, error returns, key transitions and
  the eight-byte ABI boundary. Initial baseline timer flake passed isolated and
  on the subsequent full run (544 passed before this layer).
- Cohort: controller-dependent games across the 52 A/A? and x86 groups;
  no game is promoted based on these unit tests.
- Remaining: cfgmgr32/SetupAPI tree and properties, Xbox CI/deploy and sweep,
  physical input validation, then graphics/kernel contracts.

## Layer 2 — controller configuration tree and SetupAPI identity

- Added a finite root/controller tree shared by setupapi and cfgmgr32 exports:
  locate, child, parent, sibling, device ID/size and device status. Invalid
  pointers, flags, missing nodes and insufficient buffers return CONFIGRET
  errors; leaf traversal terminates rather than succeeding with uninitialized
  output. cfgmgr32 now uses bridge routing instead of console shell exports.
- HID device-info records now use the setup class GUID, distinct from the HID
  interface GUID. Added A/W instance IDs and typed registry properties, including
  correctly terminated REG_MULTI_SZ hardware IDs and byte-sized property buffers.
- References: Wine dc26e618 setupapi/devinst.c, setupapi/stubs.c and cfgmgr32.spec.
  The inspected Wine child stub returns success without filling the output;
  Nativra implements its own consistent finite tree instead of copying that stub.
- Tests: 553 passed, 1299 platform-skipped, zero failed. Actual HidBridge and
  ControllerConfiguration compile in the portable suite. Tests cover tree
  termination, ID round-trip, short buffers/canaries, return codes, status,
  shared exports, multi-string encoding and class/interface distinction.
- Scope: x64 HID discovery across Unity/Rewired and other SetupAPI clients.
  x86 SetupAPI still enumerates no devices; no claim of a full HID report stack.
- Remaining: CI and multi-game console sweep; Ex APIs, arbitrary device classes,
  multi-controller HID enumeration and physical input verification remain open.

## Layer 3 — D3D9 capability query contracts

- Compared DXVK f20f363 src/d3d9/d3d9_adapter.cpp with the native bridge.
  Format queries now validate adapter/resource inputs and reject unimplemented
  displacement maps and non-lockable plain depth surfaces. Depth matching checks
  the color target too. NONMASKABLE MSAA no longer advertises single-sample
  support; unknown formats and out-of-range sample types are rejected.
- Added ten native D3D9 API regression assertions, retaining supported texture,
  lockable depth, single-sample and color/depth cases. Native WARP execution is
  pending Windows CI; it cannot run on this Mac.
- DXVK 8d252af DOTPRODUCT3 optimization fix does not apply: Nativra retains all
  prior fixed-function color stages. No corresponding code change was made.
- Cohort: all 17 catalog D3D9 entries, overlapping the 23-entry x86 cohort.
  These are capability-contract corrections, not evidence that 17 games now run.
- Remaining: native CI, bounded broad sweeps, shader/resource gaps from actual
  reports. No title-specific overrides or user workarounds were introduced.

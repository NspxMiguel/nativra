## Layer 2 — controller configuration tree and SetupAPI identity

- Added a finite root/controller tree shared by setupapi and cfgmgr32 exports:
  locate, child, parent, sibling, device ID/size and device status. Invalid
  pointers, flags, missing nodes and insufficient buffers return CONFIGRET
  errors; leaf traversal terminates rather than succeeding with uninitialized
  output. cfgmgr32 now uses bridge routing instead of console shell exports.
- HID device-info records now use the setup class GUID, distinct from the HID
  interface GUID. Added A/W instance IDs and typed registry properties, including
  correctly terminated REG_MULTI_SZ hardware IDs and byte-sized property buffers.
- References: Wine dc26e618 setupapi/devinst.c, setupapi/stubs.c and cfgmgr32.spec.
  The inspected Wine child stub returns success without filling the output;
  Nativra implements its own consistent finite tree instead of copying that stub.
- Tests: 553 passed, 1299 platform-skipped, zero failed. Actual HidBridge and
  ControllerConfiguration compile in the portable suite. Tests cover tree
  termination, ID round-trip, short buffers/canaries, return codes, status,
  shared exports, multi-string encoding and class/interface distinction.
- Scope: x64 HID discovery across Unity/Rewired and other SetupAPI clients.
  x86 SetupAPI still enumerates no devices; no claim of a full HID report stack.
- Remaining: CI and multi-game console sweep; Ex APIs, arbitrary device classes,
  multi-controller HID enumeration and physical input verification remain open.

## Layer 4 — shared kernel32/ntdll heap contract

- Added an executable audit against Wine DLL .spec files using the real guest
  registrations (tools/wine-import-audit), not a grep estimate. Baseline ntdll
  had only 11 named exports registered; the six heap entries bring that to 17.
  This is an import inventory, not a semantic coverage or game success score.
- Added RtlAllocateHeap, RtlFreeHeap, RtlReAllocateHeap, RtlSizeHeap,
  RtlValidateHeap and RtlGetProcessHeaps sharing kernel32's guest allocations.
- Fixed HEAP_ZERO_MEMORY growth (including padding/reused blocks), preserved
  allocations on HEAP_REALLOC_IN_PLACE_ONLY failure, rejected alignment overflow,
  tracked requested sizes and validated allocation/heap handles. C realloc's
  null-pointer behavior stays in GuestHeap; the Windows heap APIs reject null
  realloc as Wine does.
- Reference: Wine dc26e618 dlls/ntdll/heap.c and ntdll.spec. No copied code.
- Tests: 557 passed, 1299 platform-skipped. New tests cover overflow, reused
  dirty memory, padding, in-place failure and cross-DLL allocation ownership.
  An existing GetProcAddress test incorrectly called HeapAlloc with a null heap;
  it now obtains GetProcessHeap before testing the resolved function pointer.
- Cohort: 23 catalog X86 games plus guest runtimes. No console claim yet.
  Independent heap arenas, heap exception flags and broad ntdll coverage remain.

## XInput audio-query contract review

- Microsoft documents both audio directions/counts as optional. Corrected the
  new endpoint query to accept omitted directions, clear a supplied nonempty
  output buffer and leave zero-capacity buffers untouched. This avoids making
  discovery fail merely because an engine requests only one direction.
- Reference: https://learn.microsoft.com/en-us/windows/win32/api/xinput/nf-xinput-xinputgetaudiodeviceids
- Tests: 558 passed, 1299 platform-skipped; added optional-output and buffer-boundary
  checks against the actual PadBridge delegate.
- Sweep also records PlayerPrefsException on Unity: no x64 registry bridge was
  found, while x86 has persistent registry support in GuestKernel.Libraries.cs.
  A persistent x64 registry is the next high-reach layer to investigate; the
  log alone does not prove it is the only remaining Unity startup problem.

## Xbox regression found — build 502

- The first x64 result in the second sweep stopped before loading the game:

- Added MarshalDelegate="Required All" for the native bridge namespace in rd.xml.

  https://learn.microsoft.com/en-us/windows/uwp/dotnet-native/runtime-directives-rd-xml-configuration-file-reference

## Layer 5 — persistent x64 registry values

- Added A/W registry create/open/query/set/delete/close/flush callbacks to the
  x64 bridge, including registry API-set aliases. Each Steam app has its own
  snapshot in LocalState/registry/<appid>.txt; no host registry is modified.
- Typed values preserve DWORD/binary bytes and translate text between UTF-16 and
  the guest's existing Windows-1252 codec. Queries report required byte lengths
  without writing short buffers. Both sign-extended and zero-extended root HKEYs
  are accepted; synthetic handles never escape to the host registry functions
  implemented by this bridge.
- Snapshots are written to a temporary file then replaced; I/O failures return
  ERROR_WRITE_FAULT instead of claiming a durable save. Keys and values use
  base64 records so user names/newlines cannot corrupt serialization.
- Reference: Wine dc26e618 dlls/kernelbase/registry.c, RegCreateKeyExW,
  RegSetValueExW and RegQueryValueExW; existing x86 GuestKernel.Libraries.cs.
- Tests: 563 passed, 1299 platform-skipped. New tests cover restart persistence,
  Unicode settings, ANSI/Wide byte counts, short-buffer canaries, delete/missing
  behavior and write failures. Console validation pending AOT artifact.
- Cohort: registry-backed engines/settings, including the 31-entry Unity family;
  observed PlayerPrefs failure is the motivating shared contract, not a claim
  that all 31 titles are fixed. Enumeration, notifications, security/access
  rights, volatile keys and WOW64 registry views remain unsupported. Value size
  is limited to 16 MiB to fit the app budget.

# First documented game-menu image on Xbox Series X

Date: 2026-09-23. App: Nativra (package identity NSPX.Kiosk).
Game: Seraph's Last Stand, Steam app 1919460, Unity 2021.3.0f1.

![Seraph's Last Stand main menu captured from the Xbox Device Portal](seraph-menu-build174.png)

Original 1920×1080 Device Portal capture from build 174, without AI generation,
retouching or a mockup. This records the first complete menu screenshot retained
from this work session, not a claim that every earlier experimental build failed
to draw. The creator credit is the app's overlay. No game binaries are included.

## What this proves

- The actual game menu reached the console display through the native loader,
  D3D11 bridge and XAML frame mirror. It is not PC streaming.
- Unity reported Direct3D 11, feature level 11.0, SraKmd_arden and 4096 MB VRAM.
  That reported adapter value is not proof of the app's actual memory budget.
- The image became visible after ResizeBuffers rebound the mirror to the new
  1920×1080 texture and readback handled RGBA-to-BGRA conversion correctly.

## Measured fixes leading to this milestone

| Problem | Evidence and change |
| --- | --- |
| Static TLS missing on game threads | Windows-owned packaged TLS carriers replaced unsafe private TLS vectors. |
| Heap corruption | The swap-chain description was freed twice; the duplicate free was removed. |
| Wrong executable selected | UnityCrashHandler64 was excluded from the main executable selection. |
| Native plugins missing | Unity's x86_64 plugin directory was mapped; extensionless DLL lookup was fixed. |
| Black or stale image after resize | Mirror resources were rebound to the new back buffer, with owned references and format conversion. |
| Input host ignored without a physical pad | Host key events were merged with gamepad input. Click dispatch remains under test. |

## Not yet verified or working

- A stable playable match, repeated launches, and full controller interaction.
- Smooth presentation: the mirror had a hard 50 ms interval (20 FPS maximum).
  Render-loop counters around 53–60/s did **not** mean 60 displayed FPS. Miguel
  independently observed roughly 15–20 FPS in the menu.
- Build 176's real window-procedure dispatch regressed startup in one run:
  access violation at UnityPlayer.dll+0x6CF0F6, reading 0x1E64. Delaying synthetic
  startup messages until the first rendered frame is a pending test, not a
  confirmed fix.
- SteamAPI initialization reports failure; no fake authentication success was
  substituted. Multiplayer, friends, invitations and achievements are unverified.
- FMOD reports no working output device and falls back to silent output.
- LEGO Jurassic World has not been validated.

## Changes awaiting console validation

- `e96292c`: Downloaded filter, local/developer-folder discovery, PT/EN labels,
  and markers to exclude interrupted new downloads. Legacy detection uses a
  nonempty top-level executable; it is not a full integrity check.
- `e06af07`: user-selected launch from Steam details and library tiles, removal
  of automatic game startup by default, and removal of the 20 FPS mirror cap.
  A native game can currently be loaded only once per app process; restart is
  required before another launch. This is not seamless lifecycle support.

## Publication policy

Source changes, build history and sanitized milestone evidence belong in this
repository. Account tokens, QR sign-in challenges, game files, crash dumps and
private work notes do not. Raw logs are not automatically safe to publish.
The screenshot above was visually reviewed before publication.

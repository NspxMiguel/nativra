## Goal 1 — x86 layer

### Done

**Portable core (`x86/Nativra.X86`, netstandard2.0).** Referenced by the UWP
app; unit-tested on net8.0 on the runner and locally.

- `Cpu/Decoder.cs` — instruction length + operand decoder for the one-byte,
  `0F`, `0F38`/`0F3A` and x87 maps, with VEX length skipping. Getting length
  exact is what lets the JIT step over instructions it does not translate.
- `Cpu/Interpreter*.cs` — a reference interpreter: integer ALU, shifts/rotates,
  mul/div/imul, BCD, string ops (`rep` forms), and the two-byte map
  (setcc/cmovcc, bit ops, movzx/movsx, shld/shrd, cmpxchg, xadd, bswap, …).
- `Cpu/Fpu.X87.cs`, `Cpu/Fpu.Sse.cs` — the x87 stack (80-bit registers kept in
  FXSAVE layout), MMX, and SSE/SSE2. CPUID advertises only what the interpreter
  actually executes (up to SSE2).
- `Cpu/GuestMemory.cs` — a 4 GB paged guest address space with two backings: a
  managed one for the interpreter and the tests (any OS), and a native 4 GB
  reservation where guest address + host base = host pointer, which the JIT
  addresses directly.

**Differential test against real silicon.** `x86/harness/oracle.c` is a 32-bit
program that, for each snippet in `snippets.txt`, builds random guest states,
runs the snippet natively (under WoW64 on the runner), and prints the state
before and after — registers, EFLAGS, the full FXSAVE image, and the touched
data and stack. `InterpreterOracleTests` replays each input through the
interpreter and checks it reaches the same state. **132 snippets pass
bit-for-bit**, covering every category above. The only masked fields are the
sticky FP exception-status bits (FSW/MXCSR), which no software interpreter
reproduces and no correct guest depends on; the JIT, running on real silicon,
reproduces them exactly.

**CI.** `.github/workflows/x86-harness.yml` (windows-latest) builds the oracle
with MSVC's x86 toolchain, regenerates the vectors on the runner's own
processor, and runs the suite. Independent of `build-uwp.yml`.

**x86-to-x64 block JIT (`x86/Nativra.X86/Jit`).** Translates a run of
straight-line guest code into one self-contained x64 function and caches it by
guest EIP.

- Guest GPRs are pinned to host GPRs (`Ctx.GuestToHost`), so a guest ALU
  instruction becomes the identical x64 instruction on the mapped registers and
  its EFLAGS come straight from the host processor — no flag recomputation, and
  a natural bit-for-bit match with real silicon.
- Guest memory is addressed as `host_base + guest_address` (the native 4 GB
  reservation), the standard box64/blink trick, so a load is one `lea` for the
  address and one `mov` through the base register.
- `CodeCache` publishes each block into its own page, committed RW, filled, then
  flipped to RX — the console's W^X route (RWX up front is refused; JitProbe
  measured this).
- The engine is JIT-first with an interpreter fallback: a block ends at the
  first control-flow or untranslated instruction and the reference interpreter
  runs that one, so the JIT is only ever faster, never a second source of truth
  that could diverge.
- Covered inline: the ALU set (reg/reg, reg/mem, mem/reg, immediates), mov in
  every form, lea, test, inc/dec/neg/not, shifts/rotates by imm/1/CL, mul/imul/
  div/idiv, imul 2- and 3-operand, movzx/movsx, setcc, cmovcc, bswap, push/pop.
- The **same hardware oracle** validates the JIT: every case runs through the
  compiled code and is compared to real silicon with **no flag mask at all**
  (the flags are the host CPU's own). 308 differential checks pass, plus
  end-to-end engine tests (a summation loop, an array walk through guest memory,
  a call/ret across the guest stack, block-cache reuse).

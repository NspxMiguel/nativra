# WP03 implementation report

Date: 2026-10-24. Branch: `codex-wp03`.

## Delivered

Implemented WP03 from `docs/PROTON-PORT-PLAN.md`: verified chunk resume and repair,
manifest-based capacity planning, bounded CDN/decryption/decompression handling,
sanitized installation diagnostics, and copy/verify/commit storage moves that
retain sources until publication. Added portable helper tests and integration
fixtures linking the actual C# downloader/depot/storage implementation. Extended
Windows harness path triggers and tooling classification regression coverage.

The persistent payload is the checkpoint; every reused range is checked against
the current app/depot/manifest/file's length and SHA-1. Embedded manifest and
depot IDs must match the request before any reuse. No completion percentage,
file size or old marker bypasses verification. Completion publishes only after
readback. Legacy installations require a new verification pass. Destination
conflicts preserve both trees and return an actionable error rather than merging
or overwriting saves. Reserve defaults to 64 MiB and is configurable through
`DownloadCheckpoint.ReserveBytes`; unknown capacity is explicit. Buffer limits
are 4 MiB decoded chunks, 8 MiB CDN chunks, 32 MiB manifest responses and 64 KiB
move buffers; manifest metadata still scales with manifest entries. Sequential
chunk processing prioritizes bounded memory and verified restart; throughput on
real storage has not been benchmarked.

Read the evidence policy, Xbox port boundary, WP03, compatibility and blockers,
and the parity/library/architecture baseline documents. Historical evidence and
remaining stage unknowns are recorded in `docs/progress/wp03-installation.md`.
Duck's reported failure near 50% has no supplied first-error log; its actual cause
cannot be determined here. Runtime/CLR work is outside this package.
